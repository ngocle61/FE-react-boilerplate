# Terms defined in the docs

- **It creates**: | Layer  | Files                                                                                                                       |  [generators\README.md]
- **Errors come from `fieldState`**: Field components read the message from `fieldState.error`. Do not thread `error={errors.x?.message}` through props.  [global-skill-agent\form.md]
- **Layout with `FieldGroup`**: Stack fields and the submit button inside `FieldGroup`; group checkboxes and radios with `FieldSet` + `FieldLegend`.  [global-skill-agent\form.md]
- **Schema factories in `schema/`**: Declare `create<Form>Schema = (t: TFunction<'<namespace>'>) => z.object(...)` in `schema/<form>.schema.ts` so messages are localized.  [global-skill-agent\form.md]
- **Zod 4 syntax**: Use top-level format schemas (`z.email()`, `z.url()`, `z.uuid()`) and the `{ error }` parameter. Do not use the deprecated `z.string().email()` chain or `message`.  [global-skill-agent\form.md]
- **Types are inferred**: `types/<form>.type.ts` exports `type <Form>Values = z.infer<ReturnType<typeof create<Form>Schema>>`.  [global-skill-agent\form.md]
- **Defaults are constants**: `constants/<form>.constant.ts` exports `<FORM>_DEFAULT_VALUES`; always pass `defaultValues` to `useForm`.  [global-skill-agent\form.md]
- **Coordinate components using shared state**: Group related widgets that manage joint behaviors (e.g., tabs, select menus, accordions) into compound component groups sharing React Context.  [global-skill-agent\react.md]
- **Access implicit state**: Child elements must consume the shared context implicitly, shielding the developer from having to bind change events and properties manually.  [global-skill-agent\react.md]
- **Isolate state management**: Decouple the component layout from the state store mechanics.  [global-skill-agent\react.md]
- **Define clear context interfaces**: Context values must follow a strict `{ state, actions }` contract to make state interactions explicit and allow easy mocking or dependency injection.  [global-skill-agent\react.md]
- **Lift state for sibling components**: Move states to Context Providers when multiple component nodes must respond to changes together.  [global-skill-agent\react.md]
- **Avoid custom render properties**: Prefer the clean use of standard `children` rendering over custom render hooks/functions (e.g. `renderHeader`, `renderFooter`).  [global-skill-agent\react.md]
- **No forwardRef**: When React 19+ is used, write components without using `forwardRef`. Bind the component's `ref` attribute directly as a parameter prop.  [global-skill-agent\react.md]
- **Use use() hook**: Substitute `useContext` with the native `use()` hook to read context resources dynamically or inside control statement blocks.  [global-skill-agent\react.md]
- **Mandatory in this template**: The project runs React 19 (see [package.json](../package.json)), so code never uses `forwardRef` or `useContext`. This includes the primitives in `src/_widgets/ui`.  [global-skill-agent\react.md]
- **The URL is the source of truth**: Filters, search, pagination, the calendar view and date — anything a user would expect to survive a reload, a shared link or the Back button — live in the search params, never in `useState`.  [global-skill-agent\react.md]
- **Back and forward restore the form**: Mount the `-filters` component with `key={useHistoryRestoreKey()}` so a history pop remounts it with the restored URL values.  [global-skill-agent\react.md]
- **Always read the rules first**: Upon receiving a task or entering the environment, scan all files in `global-skill-agent/` to ensure compliance with every numbered rule (1 to 37).  [global-skill-agent\README.md]
- **Verify before finishing**: Run `npm run verify` (typecheck, lint with architecture boundaries, tests). Work that fails it is not done.  [global-skill-agent\README.md]
- **No exceptions**: Writing code that violates any rule in these documents is considered incorrect.  [global-skill-agent\README.md]
- **Never guard inside a page**: A page component must not redirect or render 403 based on the user. Mount it under the right guard instead.  [global-skill-agent\routing.md]
- **Redirect targets are validated**: Read `?redirect=` only through `toSafeRedirectPath`; it rejects absolute, protocol-relative and backslash URLs.  [global-skill-agent\routing.md]
- **Sign-in does not navigate**: A successful sign-in only starts the session (`sessionService.start`). `GuestRoute` performs the redirect.  [global-skill-agent\routing.md]
- **Roles and permissions are constants**: `ROLES` (`core/constants/roles.constant.ts`), `PERMISSIONS` (`permissions.constant.ts`, `resource:action` strings) and `ROLE_PERMISSIONS` (`role-permissions.constant.ts`).  [global-skill-agent\routing.md]
- **Route requirements are declared once**: `ROUTE_ACCESS` (`route-access.constant.ts`) is passed to `createGuardedRoute` and to the matching `NAVIGATION_GROUPS` item. The sidebar and the router can never disagree.  [global-skill-agent\routing.md]
- **Backend permissions win**: If the user DTO carries `permissions`, `resolvePermissions` uses them instead of the role map. Keep `ROLE_PERMISSIONS` as the fallback policy.  [global-skill-agent\routing.md]
- **Check permissions, not roles**: Use `useAccess().can({ permissions, mode })` in logic and `<Can permissions={[...]}>` around UI. Comparing `user.role === ROLES.ADMIN` in components is forbidden.  [global-skill-agent\routing.md]
- **`mode` is explicit when mixing**: A requirement defaults to `all`. Pass `mode: 'any'` only when one of several permissions is enough.  [global-skill-agent\routing.md]
- **One route file per module**: `src/router/routes/<module>-routes.ts` exports `<module>Routes: RouteObject[]`. `routes.tsx` only spreads them into the tree.  [global-skill-agent\routing.md]
- **Paths are constants**: Every path comes from `ROUTE_PATHS`. Build links with the same constant.  [global-skill-agent\routing.md]
- **Breadcrumbs through `handle`**: Set `handle: { breadcrumb: '<i18n key>' } satisfies RouteHandle` on routes that should appear in the header breadcrumb. Nested routes add their own crumb.  [global-skill-agent\routing.md]
- **Errors stay inside the layout**: `createGuardedRoute` attaches `RouteErrorPage` as `errorElement`, so a crashing module keeps the shell. Do not wrap pages in extra error boundaries.  [global-skill-agent\routing.md]
- **Folder tree mirrors the route tree**: `/calendar` is `src/modules/calendar/calendar.tsx` and `/calendar/events/:id` lives at `src/modules/calendar/event-details/` (Rule 28).  [global-skill-agent\routing.md]
- **Sign-in seeds the cache**: `sessionService.start(session)` writes the signed-in user into the query cache and the tokens into the store, so the shell renders without a second `/users/me` request.  [global-skill-agent\routing.md]
- **`MainLayout` waits for the user**: It renders `PageLoader` until the current user query resolves, so guards, the sidebar and pages always see a user.  [global-skill-agent\routing.md]
- **Guards stay components**: `ProtectedRoute`, `GuestRoute` and `PermissionRoute` keep reacting to the store at render time, because a session can end while the user stays on a page, and route middleware only runs on navigation.  [global-skill-agent\routing.md]
- **Use `truncate`**: Prefer `truncate` utility shorthand over `overflow-hidden text-ellipsis whitespace-nowrap`.  [global-skill-agent\shadcn.md]
- **No manual `dark:` overrides**: Manage dark theme colors via native CSS variable swaps under `@theme` (configured in [index.css](../src/index.css)).  [global-skill-agent\shadcn.md]
- **Use `cn()`**: Apply conditional classes through the `cn` helper instead of writing raw template string expressions.  [global-skill-agent\shadcn.md]
- **No manual z-index on overlays**: Elements like Dialog, Sheet, and Popover manage stack indexing natively.  [global-skill-agent\shadcn.md]
- **Use FieldGroup & Field**: Do not structure forms with generic layout divs or raw grid layouts. Arrange inputs inside `FieldGroup` and individual label-control pairs inside a `Field`.  [global-skill-agent\shadcn.md]
- **Use ToggleGroup**: For option lists consisting of 2 to 7 elements, use `ToggleGroup` instead of rendering buttons manually with active state tracking.  [global-skill-agent\shadcn.md]
- **Checkboxes & Radios**: Group checkboxes/radios using `FieldSet` and `FieldLegend` instead of normal headings and wrappers.  [global-skill-agent\shadcn.md]
- **Custom Triggers**: Use `asChild` (Radix) or `render` (Base primitives) to map custom trigger actions without introducing extra DOM wrappers.  [global-skill-agent\shadcn.md]
- **Card Composition**: Break card designs into semantic elements: `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, and `CardFooter`. Avoid wrapping entire layouts inside `CardContent` alone.  [global-skill-agent\shadcn.md]
- **No isLoading on Button**: Do not add custom loading state boolean props directly to Buttons. Instead, compose using a Spinner icon along with `data-icon` and the standard `disabled` attribute.  [global-skill-agent\shadcn.md]
- **Tabs Triggers**: Map all `TabsTrigger` buttons inside a `TabsList` container. Never render triggers directly inside the root `Tabs`.  [global-skill-agent\shadcn.md]
- **Avatar Fallbacks**: Always couple `Avatar` elements with an `AvatarFallback` container to handle cases where assets fail to load.  [global-skill-agent\shadcn.md]
- **The page never scrolls for a table**: List pages live inside the `h-svh` app shell. The content wrapper under `PageHeader` takes `min-h-0 flex-1`, so the toolbar, the table and its footer share the height left in `main`.  [global-skill-agent\shadcn.md]
- **The footer stays at the bottom**: The summary and pagination sit in a `shrink-0` footer under the growing container, so they stay at the bottom edge with one row, the empty state or the loading row.  [global-skill-agent\shadcn.md]
- **Small screens keep a usable table**: The container keeps `min-h-48`; only when the toolbar leaves less room than that does `main` scroll as a fallback.  [global-skill-agent\shadcn.md]
- **Use data-icon for Button Icons**: Icon alignment within buttons is controlled via `data-icon="inline-start"` or `data-icon="inline-end"` properties.  [global-skill-agent\shadcn.md]
- **No explicit sizing**: Do not apply width/height classes (e.g., `w-4 h-4` or `size-4`) to icons placed inside buttons or input containers; sizing is managed by the design system styling files.  [global-skill-agent\shadcn.md]
- **Object Imports**: Pass icons as component objects, not as dynamic string keys.  [global-skill-agent\shadcn.md]
- **Registry reference first**: Before building or changing a primitive, read the latest shadcn source for it. Run `npx shadcn@latest view <component>` or open `https://ui.shadcn.com/r/styles/radix-nova/<component>.json`.  [global-skill-agent\shadcn.md]
- **Upgrading a primitive**: Diff the new registry source against the ported files and merge the changes manually.  [global-skill-agent\shadcn.md]
- **No atomic design directories**: Do not use `atoms`, `molecules`, or `organisms` sub-directories in `src/_widgets/ui`.  [global-skill-agent\structure.md]
- **One folder per primitive**: Every primitive lives in `src/_widgets/ui/<component>/`. The folder name is the component family (`dialog`, `sidebar`, `select`).  [global-skill-agent\structure.md]
- **One component per file**: Each part of a compound component gets its own file named after it (`dialog-content.tsx`, `dialog-title.tsx`). Never bundle several components into one file.  [global-skill-agent\structure.md]
- **Class merging**: Import `cn` from `src/_widgets/lib/cn.ts`, which knows the custom token scales (`h-input`, `rounded-card`, `shadow-card`, `text-md`).  [global-skill-agent\structure.md]
- **Two entrypoints**: Primitives are re-exported from `src/_widgets/public-api.ts` and imported through `@ui`. Form fields are re-exported from `src/_widgets/ui/form/public-api.ts` and imported through `@ui/form`.  [global-skill-agent\structure.md]
- **Feature isolation**: Organise components and code inside `src/modules` by domain features.  [global-skill-agent\structure.md]
- **Service-Query-Converter structure**: Follow a clean separation of concerns within each module folder. Data flows `core/apis → services → queries → hooks (select: converter) → components`:  [global-skill-agent\structure.md]
- **`schema/`**: Form validation schemas (e.g., Zod schemas).  [global-skill-agent\structure.md]
- **`types/`**: Pure interfaces and typings.  [global-skill-agent\structure.md]
- **Conditional sub-directories**: Module sub-directories must only be created when they actually contain files used by the module.  [global-skill-agent\structure.md]
- **Relative imports inside core**: Code inside `src/core` must use relative imports (`./` or `../`) to import other `core` files. Do not use `@core/*` aliases from within the core layer.  [global-skill-agent\structure.md]
- **Core decoupled from modules**: The core layer must never import or depend on anything inside `src/modules`. Shared API structures or global interfaces belong in `src/core/types`.  [global-skill-agent\structure.md]
- **Decouple utility functions**: Place logic processing helpers, calculations, or pure parsing utility functions in a `utils` folder or file.  [global-skill-agent\structure.md]
- **No inline helpers**: Do not declare logic utility functions inline within mappers, services, hook files, or component bodies.  [global-skill-agent\structure.md]
- **Name files after components**: Component files must be named after the component (e.g., `app-sidebar.tsx`) rather than using `index.tsx`.  [global-skill-agent\structure.md]
- **No barrel index.ts exports**: Do not create `index.ts` files inside UI components or feature folders to re-export files.  [global-skill-agent\structure.md]
- **Use direct imports for shared components**: Always import shared components pointing to their specific named files.  [global-skill-agent\structure.md]
- **Import widgets from their entrypoint**: UI primitives come from `@ui`; form fields (`InputField`, `SelectField`, …) come from `@ui/form`. Never deep-import files under `src/_widgets`.  [global-skill-agent\structure.md]
- **Support folders stay at the module root**: `hooks/`, `utils/`, `types/`, `converters/`, `services/`, `queries/`, `schema/`, `constants/` are not part of the tree and are exempt from the naming rules.  [global-skill-agent\structure.md]
- **Non-components leave the tree**: Formatters, calculations, and other pure helpers belong in `utils/` per Rule 10, even when only one component uses them.  [global-skill-agent\structure.md]
- **DTO types are inferred, never declared**: `src/core/types/<entity>.dto.ts` only re-exports `z.infer` / `z.input` of generated schemas. A field the UI needs but the API does not send belongs in a converter's UI model, not in the DTO.  [global-skill-agent\structure.md]
- **Use Flex/Grid gaps**: Prefer using `gap-*` in flex/grid layouts over `space-x-*`/`space-y-*` utilities for simpler responsive adjustments.  [global-skill-agent\style.md]
- **Container Queries**: Use native container class names or custom `@container` styles directly to size components based on parent container width, rather than global screen width.  [global-skill-agent\style.md]
- **Resources are declared once**: `src/core/types/i18next.d.ts` maps every namespace to its `en.json` through `CustomTypeOptions`. Adding a locale namespace means adding it there too; `t()` then rejects any key that does not exist.  [global-skill-agent\typescript.md]
- **Server keys are narrowed, not cast**: Keys that arrive at runtime (error message keys) go through a type guard backed by `i18n.exists` before reaching `t()`, falling back to a known key.  [global-skill-agent\typescript.md]
- **For any other kind of module**: 1. Add permissions to `PERMISSIONS` and grant them in `ROLE_PERMISSIONS`.  [README.md]
